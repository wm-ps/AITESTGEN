# Story 6.6: Allure test report

Status: done

## Story

As a member or admin,
I want a polished, shareable HTML report for each test run,
so that I can review results in detail and pass them to people who don't use Vantage day to day.

## What it does today

- **Produced for every finished run.** When a run finishes, Vantage builds a Vantage-branded report from the run's Allure results. It is a single self-contained HTML page ("Test run report — Generated by Vantage from the Allure results of this run").
- **What the report contains:**
  - **Overview:** overall result, start and finish times, duration, counts of passed / failed / broken / skipped, pass rate and a pass-rate bar.
  - **Filters:** All / Passed / Failed / Broken / Skipped, with counts.
  - **Per test:** status, duration, start time, the error and its stack trace, the test's steps, and attachments.
    - Screenshots appear in a gallery that can be enlarged.
    - Text attachments can be expanded.
    - The Playwright trace and other files can be downloaded.
- **Size limits.** Large attachments are left out and listed as "Not included" with their size. If the whole report would still be too large, no report is produced for that run.
- **Opening it.** **View report** on run detail opens the report in a new tab. It has a stable link per run, and the run-completed email links to it.
  - While it loads: "Opening report" with bouncing dots.
  - If there is no report (still being built, cancelled run, or too large): "The report may still be generating, or this run didn't produce one."
- **Not for viewers.** Viewers get "Reports aren't available for view-only access. Screenshots and traces are on the run in Vantage."
- **Cancelled runs** never get a report.

## Acceptance criteria

1. **Given** a run finishes, **when** its results are processed, **then** a single-file Vantage-branded HTML report is produced and linked to the run.
2. **Given** a member or admin on run detail, **when** they click **View report**, **then** the report opens in a new tab, showing the overview, filters and per-test detail with attachments.
3. **Given** an attachment is too large, **when** the report is built, **then** it is listed as "Not included" with its size instead of being embedded.
4. **Given** the report as a whole is too large, or the run was cancelled, **when** the user opens View report, **then** they are told the run didn't produce a report.
5. **Given** a viewer, **when** they open a report link, **then** they are told reports aren't available for view-only access.

## Gaps / not built

- The report is built just before the run is finally closed out, so a test that was stuck and only marked as errored at close-out may be missing from it.
- A report can't be produced for very large runs; there is no multi-file fallback.
- Flaky flags and self-healing outcomes from Vantage are not shown in the report.
