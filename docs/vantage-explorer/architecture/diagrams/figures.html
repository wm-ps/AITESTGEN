What is Explorer allowed to press?

This is decided by fixed rules in the code, never by the AI's judgement.

🟢 Presses freely

Buttons that only move around or look things up.

  • Next, Back, Continue
  • Search, Filter
  • Menu links and tabs

🟠 Depends on the app

Buttons that save something for real.

  • Save, Submit, Send, Create

Test copy of your app: allowed, so Explorer can create its own test data.
Live app: it always asks you first.

🔴 Always asks you first

Anything that can't be undone or costs money, on every app.

  • Delete, Remove, Cancel a policy
  • Pay, Buy, Transfer, Refund
  • Approve, Reject
  • Change password, Sign out
In one line: when Explorer must ask, it stops just before the button and asks “May I press Delete?” — without your yes, it never presses it. It also never presses the same final button twice.

How does Explorer know what is “correct”?

The app might have bugs. So Explorer never assumes that whatever the app does is right.

1 You and your team most trusted

Your answers to its questions — remembered forever for this app.

2 Your documents

Requirement documents or manuals you upload (PDF, Word, text).

3 Common sense

“An end date can't be before the start date.” “An email needs an @.”

4 What the app actually did never proof

Just a fact about the app — it could be a bug.

→

Step A — decide first

Before acting, Explorer writes down what should happen, using sources 1–3 only.

Step B — then look

It does the task and notes what did happen (source 4).

Step C — compare

Same? Good — it becomes a test.
Different? A possible bug. Explorer keeps the correct test, marks it “known bug”, and asks you.

In one line: Explorer decides what should happen before it looks at what does happen — so it finds bugs instead of copying them into tests.

How does one mission work?

A mission is one goal, for example “Report a claim where someone was hurt.” Explorer plans 6–15 of them after you confirm the summary.

1 Write the expectation

“The claim should be sent for urgent review.” Written before touching the app.

→

2 Open a recorded browser

Each mission gets its own robot browser, and the screen is video-recorded.

→

3 Work through it

Screen by screen: the AI decides what to type and press; safety rules are checked before every press.

→

4 Compare

The AI compares the final screen with the expectation from step 1.

✅ Matches

Marked as checked. New screens it found on the way are added to the map.

⚠️ Different

Saved as a possible bug with the screenshot and video, plus a quiet question for you: “Is this a bug, or is it correct?” It never holds anything up.

✨ New screens

Screens that only appeared because of this mission's choice are saved as hidden screens, with a note like “appears when someone was hurt”.

In one line: up to 3 missions run at the same time, each in its own browser — and you can watch every one back as a video.

How does a test earn its place?

Every test must pass four checks. Fail any one, and it is thrown away — you only ever see tests you can rely on.

🎥

1 Do it once

The AI performs the test while Explorer records every exact click and word typed.

→
🔎

2 Pick a proof

Something on screen that shows it worked, e.g. “Claim submitted”. It must not have been there before.

→
🔁

3 Replay 3 times

A plain replay robot repeats the clicks, with no AI. The proof must appear every time.

→
✂️

4 Break it on purpose

Replay with the key click removed. The proof must now disappear — so the test can catch a real problem.

✅ Proven test

Passed all four, and the app behaved as it should.

🐞 Known-bug test

Passed all four, but the app did something it shouldn't. The correct test is kept and marked “expected to fail until fixed”.

🗑️ Thrown away

Failed a check — unreliable, or couldn't tell working from broken. The reason is recorded.

In one line: every kept test comes with a video of it running and code Vantage can run straight away.

The Explorer tab — what each view is for

Five views, left to right. Anything waiting for you pulses and links straight to Questions.

1 · Live

Opens here. What the browser sees right now, the activity log, and progress through the 4 stages. Pause / Resume / Stop.

2 · Questions

“Waiting on you” first, then “Bug or correct?”, then answered ones. Click an option or type an answer.

3 · Screens

A grid of screenshots. Click one to see its actions and where each one leads.

4 · Scenarios

Proven and known-bug tests with steps, expected result, and a video. Generate tests when done.

5 · What it learned

The App Summary to confirm, what you've taught it (answers, documents, facts), and things that look wrong.
