How the projection works
  • Time grows with screens, but sub-linearly: first look stops at 150 screens or 2 hours, missions at 15, the hidden-screen search at 25 minutes. Past those caps a bigger app gets less coverage per screen, not a longer run.
  • Build + prove grows with scenario count (about 4–5 per screen), at ~20 s each with 3 in parallel.
  • Cost is projected at the measured $0.51 – $0.64 per screen.
  • For 150+ screens, set a Goal for this run (one module or flow per run). Each run then behaves like a Small or Medium one.

How a test is proven

A scenario becomes a test only if it passes all three gates. About 59% of planned scenarios are dropped here — tests that can't fail or don't behave the same way twice never reach the client.

1 · Replays without AI

The recorded steps are replayed in a fresh browser, using the exact locators the exported Playwright test will use, and must pass. The number of replays is configurable.

2 · Fails when broken

Replayed with its key step removed; the proof must not hold. This shows the test would catch a real regression.

3 · Proof is new

The proof — visible text, a URL, or an accepted API call — must not have been on screen before the test acted.

Scope

Explorer does

  • Discover screens by meaning — 1,000 customer pages count as one screen
  • Find hidden screens by trying options and amounts, and by simulating server errors inside its own browser
  • Build an access chart for each user role you add
  • Find pages no menu links to, and measure how much of the app's code ran
  • Export proven tests as standard Playwright and feed them into Journeys, Scenarios and Test cases

Explorer does not

  • Press a final Submit, Pay or Delete without the user's OK
  • Save data on production — only on environments marked non-production
  • Break the real server
  • Load, performance or security testing
  • Phone-layout (responsive) tests — not currently planned

The one-line answer for a client

On a medium application (~60 screens), one Explorer run takes about 4–5 hours of machine time and about $36 in AI. It discovers ~64 screens and produces ~130 proven, replayable Playwright tests — about 25 of them functional, the rest automatic page-quality checks — each one verified to fail when the app breaks. Re-running the tests costs nothing in AI.

Method and limits of this data

  • • Source: 5 completed Explorer runs on one test application (a CRM-style app, 57–68 screens). Treat as early results, not benchmarks; repeat on 2–3 different applications before quoting widely.
  • • Cost is tracked per run only (the gateway's reported cost for each model call). It is not broken down by stage or by page; per-screen and per-test figures are divided from the run total.
  • • Stage times are measured from each run's own stage events. “Machine total” excludes the wait for the user to confirm the App Summary.
  • • Small and Large estimates are projections from the measured per-unit rates and the default limits.
